# M2.1 — Long-Form Test Protocol

**Milestone:** M2.1 — Long-Form Editing: Performance, Memory & Cache Hardening
**Branch:** `feature/pro-editor-rebuild`
**Baseline:** `a79d0357218533d205d52b1b2da9a6fa6f697599`

## Purpose

One repeatable way to measure the long-form promise ("multi-hour, 4K projects
scrub as well as minutes-long 1080p") in real Chrome, with a short baseline, a
long project, repeated scrubs/seeks and explicit memory capture.

## Prerequisites

- Real Chrome (regular desktop Chrome, not the embedded pane). The embedded
  pane cannot substitute for this protocol.
- A long representative media file. If none is available, do not run the
  long-form half of this protocol and record the measurements as NOT VERIFIED.

## Running the protocol

1. Start the app (`pnpm dev` in `vendor/braincut`, serve the video studio at
   `/video-studio/`).
2. Short baseline: import a short 1080p clip (≤ 60 s), verify scrub/seek feel.
3. Long 1080p project: assemble ≥ 30 min of 1080p footage into a sequence
   (≥ 20 clips, ideally continuous takes).
4. Long 4K project: assemble ≥ 2 h of 4K footage, or as long as the available
   storage allows, ideally multi-hour.
5. Capture memory before the scrub loop:
   - open DevTools → Performance, or call the in-app opt-in probe
     (`collectMemory` from `vendor/braincut/src/lib/media/performance.ts`);
   - record initial heap, DOM node count, peaks cache entries/bytes, timeline
     logical clip count, frame-cache stats.
6. Repeated scrubbing: scrub/seek across the full timeline in a pattern
   (start → middle → end, repeated several times). After each pass, capture
   memory and note scrub latency / frame stalls.
7. Timeline zoom changes: zoom to fit, zoom in/out repeatedly at various
   scroll positions.
8. Waveform generation and cache eviction: import a clip, let peaks generate,
   open/close lanes, forget peaks (Preferences → clear) and confirm eviction
   behaviour and regeneration cost.
9. Source replacement: swap a clip's source (relink / re-import) and re-measure.
10. Editor close and reopen: close the tab/editor, reopen the project, confirm
    memory returns to baseline and peaks regenerate correctly.

## Not verified here

- Multi-hour 4K measurements: requires suitable long-form media on the
  operator's machine.
- Any measurement produced without a real long-form file is NOT VERIFIED and
  must not be reported as a pass.

## Cleanup

- Close the editor and DevTools; nothing is persisted by the probe
  (`collectMemory` keeps no state).
