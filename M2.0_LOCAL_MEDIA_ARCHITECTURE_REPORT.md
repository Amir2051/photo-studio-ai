## 2. Architecture as it exists (audit of `vendor/braincut`)

Two storage classes:

**A. Referenced media (originals — never copied, never modified)**
- Imported via `showOpenFilePicker`/`showDirectoryPicker` → `FileSystemFileHandle` stored per media id.
- Reopened without re-prompting only if ≤ 64 MB blob copies exist (`COPY_LIMIT` in `sources.ts`); larger files are read back from the handle with `queryPermission('read')`/`requestPermission('read')` — one-gesture grant flow ("Grant access" button / Relink dialog).
- Relink machinery: identity pointers (`id:<name>|<size>[|<lastModified>]`) map media ids → other media ids handling the "same file, different id" case; `relinkMedia`, `relinkAll`, `relinkMissing` (folder walk, name+size+duration match, ≥ half-second duration tolerance), automatic missing-detection on project open, `needsPermission` grant-all flow.
- Large plain-file drops (no handle available, e.g. permission-policy denial) hold bytes in memory and vanish on reload — **documented limitation, deliberate: never copy giant originals into IndexedDB.**
- Exports read originals (converted copies only stand in when the browser cannot decode the original format; proxies never feed exports).

**B. Derived caches (regenerable — OPFS or IndexedDB fallback)**
- OPFS via `navigator.storage.getDirectory()` when available (`opfs.ts`), else IndexedDB double-write fallback (`braincut-files`). Streaming writes only (`WritableStream<FileSystemWriteChunkType>`, memoryStream fallback keeps in-RAM buffer and flushes to IndexedDB — Safari).
- Proxy generation (`proxy.ts`): mediabunny (WebCodecs) H.264/AAC medium-quality MP4, height ≤ 540px default, never upscales, `fit: contain`, alpha discarded; output streamed into OPFS via `StreamTarget({chunked: true})`; quota preflight `ensureRoom(blob.size / 8)`; progress published in `proxyStatus`; cancellation via AbortSignal; original never touched; proxy keyed `proxy/<mediaId>.mp4`. Transcode path (`converted/`) for non-decodable inputs with the same preflight.
- Thumbnails: bounded lazy pool (`MAX_BITMAPS=400, MAX_CONCURRENT=2, MAX_QUEUED=6`) — background-friendly, not a hard virtualization.
- Export (`export/render.ts`): `ensureRoom(estimated)` preflight from measured scratch usage; output written to OPFS scratch then handed to the browser download/save-picker; picker failure/else → regular download fallback (M1.1).

**Persistence / crash safety:** IndexedDB (`idb-keyval`) for project JSON, recents (max 20), per-media source records; autosave on every edit (`scheduleAutosave`); reload-restores last project; `restoreSources` re-validates all media on open and marks missing items.

**Permissions lifecycle:** handles requested lazily (query → prompt → request, gesture-bound), revoked-permission detection on open, one-click grant-all, relink dialog with folder selection; revoked mid-session never deletes originals.

**What does not grant special access:** nothing reads arbitrary device paths; every byte access is behind an explicit user pick or a prior grant for a recorded handle.

## 3. Arbitrary limits audit

No media **size** limit and no media **duration** limit exists anywhere (`COPY_LIMIT` is a copy policy, not a cap; the rest are resource pools). Practical ceilings: available OPFS/storage quota (`ensureRoom` preflights), codec support, decoder memory — exactly what M2.0 asks for.

## 6. Memory behavior

- Source media bytes: referenced by handle (zero-copy for large files) or File reference (dropped plain files — in-memory list, not duplicated to OPFS/IndexedDB until save-as).
- Derived bytes: streamed through OPFS (`writeStream`), never held whole in RAM on the happy path.
- Metadata: probed via element/chunk events (no full read).
- Decode caches: bounded (`media-reader` MAX_PULLS/MAX_SCRUBS; image cache 512 MB; thumbnail pool bounded).
- Export: OPFS scratch preflight estimate vs quota; streaming writer.
