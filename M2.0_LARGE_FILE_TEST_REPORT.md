**Rule applied:** no large-file result is claimed from small-file tests. Every number below is a real measurement in this session or a prior one explicitly cited. Anything unmeasured says NOT VERIFIED and why.

## Environment limits of this session (binding)

- Browser under test: OpenCode-embedded Chromium **152.0.7977.167 / Electron 44.9.1** — no access to the user's regular Chrome process.
- In-page file injection tooling (`browser.files.upload`) caps at **5 MiB total** per transfer. Manual OS-level dialogs in this pane refuse protected folders (`AppData\Local\Temp\opencode`) outright and real user mouse clicks on Svelte buttons never reach page handlers.
- Therefore every *large*-file row below is a **desk/user-side test that has not been executed**. Numbers from the small-file harness cannot imply GB-scale behavior.

## NOT VERIFIED (requires your machine and your files)

| Scenario | What to record | How |
|---|---|---|
| Large MP4 (1–4 GB) | import time, resident memory (Chrome Task Manager `Shift+Esc`), preview behaviour, timeline responsiveness | drop into bin; scrub; no full-file reads occur (handle-based read + streaming proxy) |
| 4K video (e.g., 4096×2160) | decode errors? proxy generation time; preview smoothness | Create proxy from context menu; compare original vs proxy preview |
| Multi-hour (2–4 h) | timeline pan/zoom, autosave latency, open/reopen time | import a real long recording; watch memory; close/reopen project |
| Simultaneous multi-file import | parallel probe backlog, UI blocking | select 10+ files via picker |
| Interrupted import | browser tab kill mid-import; project reopens; partial files marked missing | close tab during import |
| Proxy failure | fake a bad codec (or kill OPFS quota) | Remove OPFS in DevTools → save → reopen → proxies regenerate on demand |
| Disk-full / quota exceeded | fill OPFS (DevTools) until `ensureRoom` throws | watch toast message |
| Interrupted save | kill tab during Ctrl-S | reopen project; autosave should recover |
| Large export (>1 GB) | memory profile, completion time | export with proxy source=original |
| Permission revoked mid-project | deny in Chrome site settings → reload | expect "N files missing" banner → Relink all… |

## Memory claims (measured here)

- One 279 KB MP4 imports and probes in <1 s with no observable spike in the pane.
- FFprobe numbers (M1.2): H.264 High profile, 1920×1080@30, AAC LC 48 kHz stereo. These remain the only direct codec measurements.
- **Nothing here proves GB-scale behavior. The engine's architecture (handles + streaming OPFS + per-frame decode) is the argument for memory efficiency — not measured here.**
