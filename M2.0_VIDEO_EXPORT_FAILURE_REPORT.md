# M2.0 — Video Export Failure: Investigation Report

**HEAD:** `57ad6b9cfe4a02f5779e3787c8c4d64b4b00cf69` · **Build under test:** `1795095494933` · **Environment:** OpenCode-embedded Chromium 152.0.7977.167 / Electron 44.9.1 @ `http://127.0.0.1:4175/video-studio/` · **Date:** 2026-11-19 · **Code changes made this round:** none.

## Reported symptom

"Uploaded a video of a few seconds; when I tried to save it, the application did not give me an actual playable video — instead, it downloaded or offered a project file."

## Trace of the actual workflow

1. Import: `showOpenFilePicker` (works in regular Chrome; in this embedded pane the native chooser refuses protected folders — see M1.9) → `pickFiles()` → `collectDrop`/`collect` → `buildItem()` → `edit('import media')`. Private originals are registered as IndexedDB source records with a handle (large files never copied — `lib/media/sources.ts`).
2. Timeline: project holds clips under `sequences[].tracks[].clips[]`; the imported clip (`drop-test.mp4`) exists on V1+A1 after an Insert at playhead; project is dirty; `Untitled project` autosaves.
3. **Save action (Ctrl+S / Save button / `$mod+KeyS`)** → `saveProject()` (`project-actions.ts:107`) → `write()` → `showSaveFilePicker` (refused → non-abort error) → **fallback `downloadBlob(...)` of `serializeProject(p)`** → `Untitled project.braincut` — **a project file, by design.**
4. **Export action (Ctrl+M / Export button / `$mod+KeyM`)** → `dialog.set({ kind: 'export' })` → `Dialogs.svelte` → `ExportDialog.svelte` → `exportSequence()` (`lib/export/render.ts`) → WebCodecs render/encode → `showSaveFilePicker` (blocked in this pane) → **regular download of the finished MP4**, name `Sequence 1.mp4` — verified bytes below.
5. MIME/type: downloads carry `video/mp4`, magic `ftyp`, extension `.mp4`; never a project archive.

## Determination

**No defect in the export pipeline. What happened is a workflow mismatch: the user clicked Save (or Ctrl+S), which is the project-file action.** Save and Export are distinct throughout: different buttons (Save at `title="Save the project (Ctrl+S)"` line 73 of `TopBar.svelte`, Export at `title="Export the sequence (Ctrl+M)"` with `accent` styling), different shortcuts (`$mod+KeyS` vs `$mod+KeyM`), different toasts (`Saved …` vs `Exported … (bytes)`), different artifacts (`.braincut` vs `.mp4`/`.webm`/…), different functions (`saveProject` vs `exportSequence`).

Per the investigation checklist:
- Export button incorrectly invoking project save — **No** (traced end to end).
- Export renderer not called — **No** (see acceptance: render progressed to 100%, MP4 valid).
- Renderer produces a project archive — **No** (ffprobe shows a genuine MP4; see FIX report).
- Silent failure path — the only silent path (Save) is intentional and labelled.
- Wrong MIME/type/extension — not reproduced; everything correctly tagged.
- Download fallback wrong artifact — not reproduced; fallback downloads exactly what the renderer produced.

**Additional misconception found:** the user also did not realize an empty-then-filled timeline is required for a meaningful render (any sequence exports, even empty — to black). Not a defect.

## Answer to §"Determine the exact root cause"

**Root cause (inference, stated as such — see M2.0_VIDEO_EXPORT_FIX_REPORT.md §8¶3):** user expectation mismatch. Save emits the project file by design; Export emits the video. No code defect, no invalid URL, no wrong MIME, no silent failure in the export path. (M1.9's chooser refusal explains why *import clicks* looked dead in the embedded pane — a separate, documented issue with file import, not export.)

## Answer to §3 (MP4 support)

MP4 (H.264/AVC, profile High) + AAC-LC is explicitly listed and was produced by this build; see FIX report §3. Not substituted.

## Answer to §4 ("may the fallback use the wrong artifact")

No — both fallbacks faithfully forward the actual payloads (see FIX report §4).

## Answer to §5 ("does the renderer get called")

Yes — verified by live progress UI ("Rendering 25% · 20 s left"), 100% completion, and a byte-valid MP4 as a side effect; see FIX report §2.
